Configuration is the Builder's home tab: define how your agent behaves, how it opens each conversation, and how it paces its turns. Every edit is saved to the agent's **draft** automatically. Callers only hear your changes after you [publish](/agents/deploy/versions-publishing). New to Agents? Start with the [Quickstart](/agents/quickstart).

## System prompt

The system prompt sets the personality, goals, and guardrails that steer every reply. It is capped at **64,000 tokens**, or **32,000 tokens** when the agent runs `google/gemma-4-26b-a4b-it`. The API rejects a longer prompt with `422 Unprocessable Entity`, and also a model change that would leave the prompt over the new model's cap. [`GET /v1/agent/llm-models`](/api-reference/endpoint/agent/list-llm-models) returns each model's cap as `max_system_prompt_tokens`. Keeping it under **2,000 tokens** is recommended: shorter prompts cut latency and cost, and hold the model's attention better. It can also be replaced for a single session by sending `overrides.system_prompt` when [creating the session](/agents/deploy/authenticated-sessions#overrides).

To personalize the prompt per session without replacing it, write `{{placeholders}}`: [custom variables](/agents/build/dynamic-variables#custom-variables) such as `{{customer_name}}` take the values you pass when creating the session, and [system variables](/agents/build/dynamic-variables#system-variables) such as `{{system.caller_number}}` or `{{system.today}}` are filled in by the platform.

<Tip>
Keep the prompt focused:

- State who the agent is and what it should accomplish, in a few sentences each.
- Spell out guardrails explicitly ("If asked about pricing, direct the caller to sales").
- Write for the ear: replies are spoken aloud, so ask for short, conversational answers.
</Tip>

## First message

Choose how the agent opens each conversation:

| Mode | Behavior | Field on the wire |
|---|---|---|
| **Off** | The agent stays silent and waits for the caller to speak first. | — |
| **Fixed message** | The agent opens with the exact text you provide, every time. | `first_message` |
| **Prompt** | The agent generates its opening line from instructions you provide. | `first_message_prompt` |

In the Builder, this choice is the **Opening line** group; pick **Start** first (see [When the first message starts](#when-the-first-message-starts)), then the opening line. **Off** is only available when the agent speaks first.

`first_message` and `first_message_prompt` can each hold up to 10,000 characters. The active mode (`first_message_mode`: `off`, `fixed`, or `prompt`) decides what callers hear. Both fields accept the same `{{placeholders}}` as the system prompt (see [Dynamic variables](/agents/build/dynamic-variables)), and both can be replaced for a single session by sending `overrides.first_message` or `overrides.first_message_prompt` when [creating the session](/agents/deploy/authenticated-sessions#overrides).

### When the first message starts

`prompt.first_message_start` decides whether the agent speaks as soon as the conversation connects. In the Builder this is **Start** in the First message section.

| Value | Builder label | Behavior |
|---|---|---|
| `agent_first` (default) | **Agent first** | The agent opens as soon as the conversation connects. |
| `wait_for_caller` | **Wait for caller** | The agent listens first. What it does next depends on the opening line, as described below. |

"Connects" means the callee picks up on a phone call, and the client is ready on a web or API session. Phone calls that play a [keypad](/agents/telephony/keypad) menu first are not affected by this setting.

With **Wait for caller**, the opening line works like this:

| Opening line | The caller speaks first | The caller stays silent |
|---|---|---|
| **Fixed message** | The agent lets the caller finish, then says the fixed text as its reply. It does not answer the caller with a separate turn first. | Once `first_message_max_wait_ms` has passed, the agent says the fixed text anyway. Use this when the call must always begin with the same words, such as an AI disclosure. |
| **Prompt** | The agent lets the caller finish, then replies to what they said, following your prompt instructions. It does not say the default first message. | Once `first_message_max_wait_ms` has passed, the agent generates an opening line from the prompt instructions and says it. |

`first_message_start: wait_for_caller` cannot be combined with `first_message_mode: off`: the agent would have nothing to say, so the Builder offers only **Fixed message** and **Prompt** under **Wait for caller**. The API rejects a configuration that sets both with `422`. When you switch from **Agent first** with **Off** to **Wait for caller**, the Builder moves the opening line to **Prompt**; switching straight back restores **Off**.

`prompt.first_message_max_wait_ms` (1000–5000, default `3000`) is how long the agent waits for the caller before it speaks anyway. It only applies when `first_message_start` is `wait_for_caller`. In the Builder this is **Speak anyway after**, with 1 s, 3 s, and 5 s shortcuts and a **Custom** value.

Background noise, someone else talking nearby, or a short acknowledgment such as "mm-hmm" does not count as the caller speaking. A sound that never turns into a sentence can delay the first message a few seconds past `first_message_max_wait_ms`, so treat it as the point where the agent stops waiting, not as a hard ceiling.

### Interrupting the first message

`prompt.first_message_interruptible` controls whether the caller can barge in while the first message plays. In the Builder this is **During the first message**.

| Value | Builder label | Behavior |
|---|---|---|
| `true` | **Interruptible** | The caller can interrupt the first message, as in any other reply. This is also what you get when you leave the setting unset or send `null`. |
| `false` | **Protected** | The first message always plays to the end. What the caller says during it is dropped, and the agent does not go back and answer it afterwards. |

When you write the agent without this setting, or with `null`, the first message can be interrupted. Reading the agent always returns `true` or `false`, never `null`. `conversation.interruptible` does not change this: it applies to the rest of the conversation, not to the first message. New agents can be interrupted. Set it to `false` to protect the first message.

<Warning>
Protected has a cost: a caller who starts talking over the first message cannot cut it off, and the agent never hears what they said. Keep the first message short, or use **Wait for caller** so the agent speaks into a quiet line.
</Warning>

With [Echo guard](#echo-guard) on, the first 3 seconds of the first message cannot be interrupted whichever way this is set.

## Voice

The Voice panel selects the voice your agent speaks with (`voice_id`) and its speaking language (`speaking_language`, one of the [52 supported languages](/agents/build/voice-language#speaking-language)). It also holds the text-to-speech model (`tts_model`), expressive delivery (`expressive`) and the speech recognition settings, which the API keeps in their own `asr` section: the recognition model (`asr.model`) and the multilingual recognition switch (`asr.multilingual`). See [Voice & language](/agents/build/voice-language) for all of them. The background sound (`background_sound`) and the voice effect for web calls (`effect`) have their own page, [Background sound & voice effect](/agents/build/background-sound-voice-effect).

## Conversation settings

### Turn-taking

`conversation.response_wait_ms` (300–2000, default `550`) is how long the agent waits after the caller pauses before it starts talking. In the Builder this is the **Response wait** slider, with Fast (0.45 s), Balanced (0.55 s), and Patient (0.9 s) shortcuts.

When the agent thinks the caller is mid-sentence it waits longer, up to `conversation.response_max_wait_ms` (600–4000). Leave it `null` (the default) to follow the response wait plus 0.5 s; send `0` to clear an explicit value back to automatic. A max wait below the response wait is rejected with `422`.

`conversation.eagerness` is the same setting as a preset and still works: writing `relaxed`, `balanced`, or `eager` sets the response wait to 900, 550, or 450 ms, and reads report the preset that matches the current wait.

<Note>
A short answer such as "yes" normally lands on the fast path. When the agent asks for digits or a spelled-out name, the wait is widened automatically so the caller can pause between groups.
</Note>

`conversation.speculative_response` (default `true`) lets the agent start preparing its reply while the caller may still be speaking; the draft is discarded if they continue, and tools never run before the caller's turn is confirmed. Turn it off if your [custom LLM](/agents/build/custom-llm) bills per token and you would rather not pay for discarded drafts. With it off, the response wait is added directly to every reply.

### Interruptions

- `conversation.interruptible` (default `true`): Whether the caller can barge in while the agent is speaking.
- `conversation.interruption_sensitivity` sets how much caller speech counts as an interruption:
  - `low` (**Hard to interrupt** in the Builder): The agent stops only for a firm, worded interjection, talking through background noise and short acknowledgements.
  - `balanced` (default): Interrupts on normal speech.
  - `high` (**Easy to interrupt**): The agent stops on the caller's first word.
- `conversation.interruption_ignore_phrases` (up to 50 entries of 40 characters): Backchannels such as `"uh-huh"` or `"okay"` that never interrupt the agent when the caller says only them. Matching ignores case and punctuation. Send `[]` to clear the list.

### Backchannels

An agent on a speech model that backchannels acknowledges the caller as it listens, with a short "mm-hmm" or "okay" when they pause. [Live 3](/agents/build/voice-language#live-3-full-duplex) is the one that does today. Other models ignore these settings. If callers find the acknowledgements too frequent, or feel talked over, turn them down or off.

<Tabs className="console-api">
<Tab title="Console" icon="browser">

On the agent's **Configuration** page, open **Voice details**. Both settings show once Live 3 is on.

| Setting | What it does |
|---|---|
| **Backchannels** | On by default. Turn it off to have the agent listen quietly. |
| **Backchannel strength** | How readily the agent backchannels, from 1 to 10. Lower means fewer. It starts at 6 and shows while **Backchannels** is on. |

</Tab>
<Tab title="API" icon="code">

`conversation.backchannel` is an object. A patch changes only the fields it names.

- `enabled` (default `true`): `false` turns backchannels off.
- `strength` (whole number from `1` to `10`, default `null`): How readily the agent backchannels. Lower means fewer. `null` uses the speech model's own setting, `6` on Live 3. Send `null` to go back to it. Not used while `enabled` is `false`.

```bash
curl --request PATCH "https://api.fish.audio/v1/agent/agents/$AGENT_ID/config" \
  --header "Authorization: Bearer $FISH_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "conversation": {
      "backchannel": {
        "enabled": true,
        "strength": 2
      }
    }
  }'
```

</Tab>
</Tabs>

<Note>
  With backchannels off, the agent listens quietly and acknowledges far less often. One may still come through now and then. With fewer acknowledgements, the first sound after the caller stops can also come slightly later.
</Note>

### Echo guard

Callers' devices and the phone network normally cancel the agent's echo, but in a few calls (under 3%) some echo gets through in the agent's first seconds and cuts it off.

`conversation.echo_guard` (**Echo guard** in the Builder) prevents this. For 3 seconds after the agent first starts talking, the caller can't interrupt it, and what the caller says over the agent is dropped. This holds for the first message too: with Echo guard on, its first 3 seconds cannot be interrupted, even when [`prompt.first_message_interruptible`](#interrupting-the-first-message) is `true`. [Keypad entries](/agents/telephony/keypad#keypad-input) and the [web SDK](/agents/deploy/web-sdk)'s `interrupt()` still work.

Each [channel](/agents/build/dynamic-variables#system-variables) has its own key. Set it to `true`, `false`, or `null` for the default.

| Key | Builder label | Default |
|---|---|---|
| `web_voice` | **Web calls**, including [Preview calls](/agents/test/preview-calls) | On |
| `phone_inbound` | **Inbound phone calls** | On |
| `phone_outbound` | **Outbound phone calls** | Off |

Turn it off if callers should be able to interrupt the agent within those 3 seconds.

### Call duration

`conversation.max_duration_seconds` (60–3600, default `1800`) ends the session automatically when the limit is reached.

<Note>
[Preview calls](/agents/test/preview-calls) in the Builder are capped at 10 minutes or this setting, whichever is lower.
</Note>

### Recording

`conversation.record_audio` (default `true`) stores per-speaker audio for [playback and download](/agents/monitor/conversation-history#what-gets-stored), with a per-session override on the [session request](/agents/deploy/authenticated-sessions). In the console this lives under your agent's **Settings**. Make sure callers are informed and consent where your jurisdiction requires it.

### Timezone

`conversation.timezone` is the default IANA timezone (like `Asia/Tokyo`) the agent uses for dates and times in conversation. Leave it empty for **automatic**: each session follows the caller's device or phone number, falling back to UTC. Set one when your agent serves a single region regardless of who calls. A per-session `timezone` on the [session request](/agents/build/time-timezone) overrides this. See [Time & timezone](/agents/build/time-timezone) for the full resolution order.

## Context

The `context` section holds the facts the platform tells your agent on its own, one switch each. Guardrails constrain what the agent does, context switches add to what it knows.

### Current date and time

`context.current_time` (default `true`) tells the agent today's date when a session starts and the current time before every reply, in the agent's [timezone](#timezone). In the Builder this is the **Current date & time** toggle under the time zone. Keep it on for scheduling, reminders, or any prompt that says "tomorrow" or "next Tuesday". Turn it off when the prompt states its own date, for example a role-play set on a fictional day. A session request's `context.current_time` overrides the agent's setting in either direction. See [Time & timezone](/agents/build/time-timezone).

## Autosave and publishing

There is no Save button. Each change is written to the agent's draft moments after you stop editing, and the **Saving… / Saved** indicator at the bottom-left of the page shows the current state. If a save fails, the Builder tells you and keeps your pending edits so nothing is lost.

Drafts never affect live traffic: active integrations keep using the last published version until you press **Publish**, which snapshots the draft as a new immutable version. The Publish button lights up whenever the draft differs from what is published. See [Versions & publishing](/agents/deploy/versions-publishing).

## Configure through the API

The same draft is readable and writable over REST, which is useful for provisioning agents from your own systems.

### Read the draft

```bash Request
curl --request GET "https://api.fish.audio/v1/agent/agents/$AGENT_ID/config" \
  --header "Authorization: Bearer $FISH_API_KEY"
```

```json Response (abridged)
{
  "config_hash": "sha256:5f2c1a9e…",
  "prompt": {
    "system_prompt": "You are Aria, a friendly support agent for Acme…",
    "first_message_mode": "fixed",
    "first_message": "Hi, thanks for calling Acme. How can I help?"
  },
  "voice": {
    "voice_id": "802e3bc2b27e49c2995d23ef70e6ac89",
    "speaking_language": "en"
  },
  "asr": {
    "model": "deepgram:nova-3",
    "multilingual": false,
    "strict_language": false,
    "keyterms": []
  },
  "conversation": {
    "max_duration_seconds": 1800,
    "response_wait_ms": 550,
    "response_max_wait_ms": null,
    "eagerness": "balanced",
    "interruptible": true,
    "interruption_sensitivity": "balanced",
    "interruption_ignore_phrases": [],
    "backchannel": {
      "enabled": true,
      "strength": null
    },
    "echo_guard": null,
    "speculative_response": true,
    "timezone": ""
  },
  "context": {
    "current_time": false
  }
}
```

The response also includes the `tools`, `knowledge_base`, `analysis`, and `webhooks` sections, each covered on its own page. `config_hash` identifies this draft revision; a mismatch with the published version is what marks an agent as having unpublished changes.

### Update sections

`PATCH` takes a partial body and deep-merges it into the draft: send only the sections and fields you want to change, and everything else keeps its value. Fields that hold a list (`webhooks.post_call` among them) are replaced as a whole, so send the complete list whenever you change one.

```bash
curl --request PATCH "https://api.fish.audio/v1/agent/agents/$AGENT_ID/config" \
  --header "Authorization: Bearer $FISH_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "prompt": { "system_prompt": "You are Aria, a concise support agent for Acme." },
    "conversation": { "response_wait_ms": 900 }
  }'
```

The response includes the draft's new `config_hash`. Values outside the documented limits (a system prompt over its model's cap, `max_duration_seconds` outside 60–3600) are rejected with `422 Unprocessable Entity` and the draft is left unchanged.

| Section | What it holds | Documented in |
|---|---|---|
