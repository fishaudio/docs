The All-in-One image packages the whole speech stack into one container and runs as a
turnkey single-node appliance, no Kubernetes. The model weights are baked into the
image, except in the external-weights modes, which mount them from your own
storage at run time.

Each image is built for one [billing mode](/developer-guide/self-hosting/introduction#billing),
online or offline; the container logs which at startup.

<Note>
  This page covers what the appliance is and what to plan for. The commands, tuning
  options, and troubleshooting are in the **All-in-One guide**, which you download from
  **Developer → Self Host** with the image version you run.
</Note>

## What it cannot do

The appliance runs one inference worker and one vocoder, on the cards its model
takes — see [Models](/developer-guide/self-hosting/models). It does not include
timestamp alignment, so it returns no word or segment timings. A container does not scale
itself: for more capacity, run more containers behind your own load balancer. To scale
workers and vocoders separately, use the
[Kubernetes chart](/developer-guide/self-hosting/kubernetes).

## What running it involves

One `docker run` on a host that meets the
[requirements](/developer-guide/self-hosting/requirements).
It needs:

- **The GPUs its model takes** — usually two; a Single-GPU mode, where the model offers
  one, shares one card at lower throughput.
- **One exposed port** for the API.
- **One persistent volume.** Caches, reference voice archives, and — in the offline
  mode — the [usage ledger](/developer-guide/self-hosting/air-gapped#offline-usage-accounting)
  all live there; the model weights do not.
- **The license bundle** from **Developer → Self Host**, mounted read-only. See
  [The license](/developer-guide/self-hosting/registry-access#the-license).

Everything inside the container runs as a non-root user, so a reused volume or a host
bind mount has to be writable by it.

**Plan for a slow first start.** The worker and the vocoder prepare for your GPU type
before either serves, and the health endpoint verifies the speech backend end to end
rather than reporting immediate liveness. Every start takes minutes; the first can take
much longer.

To upgrade, pull or load the new version's image and recreate the container against
the same volume.

## Tokens and tenancy

Offline, any non-empty bearer token is accepted and recorded as the billing identity:
give each tenant a stable token of its own, and control access in front of the
appliance. Online, each request must carry a
[Fish Audio API key](/developer-guide/getting-started/api-key) with credit, not the
deploy token. It is authorized against Fish Audio with no local fallback, so treat
outbound reachability as a production dependency.

## Capacity

The worker admits a bounded number of requests at once; beyond that, requests queue and
time-to-first-audio climbs. Your deployment guide gives the cap for your model; validate
latency and error rate before changing it.
